**例 8.6：赛道上的 RTDP** 习题 5.12（第 111 页）的赛道问题是随机最优路径问题。通过在一项赛道任务中比较 RTDP 与传统 DP 价值迭代算法，可以看到同策略轨迹采样的一些优点。

回顾那道习题：智能体要学习驾驶汽车绕过图 5.5 所示的弯道，保持在赛道内并尽快冲过终点线。起始状态是起跑线上所有速度为零的状态；目标状态是从赛道内部出发，在一个时间步内越过终点线所能到达的全部状态。与习题 5.12 不同，这里汽车速度没有上限，所以状态集合可能是无限的。不过，把任意策略可能从起始状态集合到达的所有状态合在一起，所得集合仍是有限的，可以将它视为本问题的状态集合。每个回合从随机选出的起始状态开始，汽车穿过终点线时结束。汽车在穿过终点线之前每走一步获得 \(-1\) 奖励。若撞到赛道边界，就被移回随机起始状态，回合继续。

与图 5.5 左侧小赛道相似的一条赛道，有 9,115 个在任意策略下可从起始状态到达的状态；其中只有 599 个**相关状态**，即从某个起始状态沿某个最优策略可达。（相关状态数是通过在 \(10^7\) 个回合中执行最优行动，统计访问过的状态而估计的。）

下表比较传统 DP 与 RTDP 对该任务的求解。数据是 25 次运行的平均值，每次采用不同的随机数种子。这里的传统 DP 是穷尽扫描状态集的价值迭代，逐个状态原地更新价值，因此每次更新使用其他状态的最新价值。这是 Gauss–Seidel 版本的价值迭代，在这个问题上比 Jacobi 版本快约一倍（见 4.8 节）。更新次序没有专门优化，其他次序可能收敛更快。两种方法每次运行的初始价值都设为零。DP 在一次扫描中状态价值的最大变化小于 \(10^{-4}\) 时被判定收敛；RTDP 则在 20 个回合中冲过终点线的平均时间似乎稳定到渐近步数时被判定收敛。此版本 RTDP 每步只更新当前状态的价值。

| 平均收敛所需更新次数 | 252,784 | 127,600 |
| 平均每回合更新次数 | — | 31.9 |

| 更新不超过 10 次的状态比例 | — | 80.51% |
| 更新 0 次的状态比例 | — | 3.18% |

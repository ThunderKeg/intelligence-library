## 4.5 异步动态规划

此前讨论的 DP 方法有一个主要缺点：它们要对 MDP 的整个状态集进行操作，即需要扫描全部状态。如果状态集很大，即使只扫描一次也可能耗费过高。例如，双陆棋的状态超过 \(10^{20}\) 个。即使每秒能对一百万个状态执行价值迭代更新，完成一次扫描也要一千多年。

**异步 DP**（asynchronous DP）算法是原地迭代式 DP 算法，但不按系统性的全状态扫描组织计算。它们以任意顺序更新状态价值，使用当时能取得的其他状态价值。有些状态可能更新了多次，另一些状态才更新一次。然而，要正确收敛，异步算法必须持续更新所有状态的价值：计算进行到某一点以后，不能永远忽略任何状态。异步 DP 算法使状态的更新选择非常灵活。

例如，一种异步价值迭代每一步 \(k\) 只选择一个状态 \(s_k\)，按价值迭代更新式（4.10）原地更新其价值。若 \(0\le\gamma<1\)，只要序列 \(\{s_k\}\) 中每个状态都出现无穷多次，就能保证渐近收敛到 \(v_*\)；这个序列甚至可以是随机的。[1] 类似地，可以交错进行策略评估更新和价值迭代更新，形成一种异步的截断策略迭代。本书不讨论它和其他更不常见 DP 算法的细节；但可以看出，几种不同的更新是构建模块，可以在各种无需完整扫描的 DP 算法中灵活组合。

当然，避免完整扫描不一定意味着计算量变少；它只意味着算法不必等一次长得令人绝望的扫描完成后，才能在改进策略方面取得进展。我们可以利用这种灵活性来选择要更新的状态，以提高算法的进展速度。可以安排更新顺序，使价值信息更有效地从一个状态传播到另一个状态。某些状态不必像其他状态一样频繁更新。如果某些状态与最优行为无关，我们甚至可以试着完全跳过它们。第 8 章会讨论其中一些思路。

异步算法还使计算与实时交互更容易交错进行。为求解某个 MDP，可以让智能体实际经历这个 MDP 的同时运行迭代式 DP 算法。智能体的经历可用于决定 DP 算法更新哪些状态；与此同时，DP 算法最新的价值和策略信息可指导智能体决策。例如，可以在智能体访问一个状态时更新该状态。这样便可以把 DP 更新集中到状态集中那些与智能体最相关的部分。

[1] 在无折扣的回合式情形中，有些更新顺序可能不收敛，但要避开这些顺序相对容易。
